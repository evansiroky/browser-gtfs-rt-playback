# Principles

The project's philosophy, written down as principles. Each is decisive: it picks a side of
a real trade-off so an implementer can resolve an unspecified case the way the author would.

No project-wide principles have been decided yet. Add them here as they are resolved,
instead of leaving them in chat or commit messages. A principle belongs in this file only
if it governs more than one spec; otherwise put it in the `## Principles` section of the
spec it governs.

Format for each entry:

```markdown
## <Short, stable name>
The principle, stated as a rule that rules something out, with the *why* that makes
the trade-off land. Specs link to it as `principles.md#<short-stable-name>`.
```
